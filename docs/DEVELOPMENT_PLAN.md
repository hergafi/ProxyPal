# ProxyPal — خارطة العمل الحالية

هذا الملف يلخص ما أُنجز وما تبقّى. المرجع التشغيلي هو `README.md`.

## منجز

### المحرّك (gateway.py + api_pool.py)
- تبديل تلقائي بين المفاتيح والنماذج، مع تفضيل النموذج المطلوب ثم المفتاح النشط.
- استراتيجيات توزيع: `sticky` و`round_robin` و`least_used`.
- حدود محلية للرموز والطلبات لكل مفتاح، مع فترة تصفير `never/daily/weekly/monthly`.
- احترام `Retry-After` و`x-ratelimit-*`، وتهدئة تصاعدية بعد أخطاء المزود.
- تجميد المفاتيح المرفوضة (401/403) أو المنتهية الرصيد (402)، وإرجاع سبب دقيق
  (`billing` / `model_unavailable` / `timeout` / `request` / `upstream`) بدل «لا يوجد مفتاح».
- تخطّي النموذج بعد أول 404 بدل تكرار فشله على كل مفتاح.
- فلترة نماذج الحماية والتصنيف (`safety`، `guard`، `moderation`، `classifier`).
- تصحيح أسماء نماذج Gemini تلقائياً (`models/...` ← `...`) لتوافق نقطة OpenAI.
- فحص المفاتيح عند الإضافة، ورفض غير الصالح فقط.
- مزودون مخصصون متوافقون مع OpenAI.
- إدارة السياق: تقليص أقدم الرسائل وتخفيض `max_tokens` بدل رفض الطلب.
- حفظ الجزء المستلم عند انقطاع البث وعدم إعادة إرساله.
- حذف أي مزود مضاف مع مفاتيحه (`DELETE /pool/providers/{name}` حتى للمزودين الجاهزين)،
  وتعديل قائمة نماذج كل مزود (`PATCH /pool/providers/{name}/models`) بحذف نموذج أو
  إضافة آخر، مع رفض 409 أثناء وجود رد جارٍ و400 للنماذج غير النصية أو أسماء غير صالحة.
- علم `switched` دقيق: يُحسب مقابل المفتاح الذي كان سيخدم الطلب فعلياً، فلا يشتعل
  مع التدوير الاعتيادي ولا يصمت عند تبديل حقيقي أثناء الرد.
- نماذج Google التي تبثّ استدلالها داخل `content` مع علم `thought` تمرَّر كـ`reasoning`.
- `POST /models/refresh`: جلب كتالوج كل مزود ثم فحص النماذج بالتوازي عبر المفاتيح
  المتاحة، بحد 45 ثانية. مفتاح يردّ 400 «Invalid Auth key» يُوقف تلقائياً ويُعاد الفحص
  بمفتاح آخر، و429 في الفحص لا يُدخل المفتاح في تهدئة. تُمسح حالات 400 القديمة
  قبل كل تحديث كي لا يبقى نموذج سليم مخفياً بسبب مفتاح رُفض.
- حماية اختيارية بـ`GATEWAY_TOKEN`، وحصر اختياري لمسار العمل بـ`WORKSPACE_ROOT`.

### الواجهة
- إعدادات التوجيه وفترات الميزانية وعرض آخر خطأ لكل مفتاح.
- إضافة/حذف المزودين والمفاتيح، مع إخفاء المفاتيح وإظهارها عند الطلب.
- مؤشرات صحة النماذج والبوابة، وشريحة «سياق مختصر».
- ثلاث لغات، خمسة خطوط، أوضاع فاتحة/داكنة، قراءة صوتية، تصدير المحادثات.
- إرسال رمز البوابة تلقائياً بعد فتح الرابط مرة واحدة بـ`?token=...`.
- إعادة تسمية المحادثة وتثبيتها في الأعلى، مع استعادة آخر محادثة بعد إعادة التحميل.
- زر Update في قائمة النماذج: يفحص النماذج بالتوازي ويعرض ملخصاً (يعمل/فشل/لم يُفحص)،
  ويخفي النماذج المرفوضة نهائياً مع إبقاء النموذج المحدد ظاهراً.
- حقل الرسالة يبقى قابلاً للكتابة والتركيز أثناء البث وبعد الرد، والمسودة لا تُمسح.
  زر الإيقاف لا يرسل المسودة بالخطأ بعد تحوّله إلى زر إرسال.
- وسم «نموذج بديل» على الرد القادم من نموذج غير الذي اختارته، مع تلميح يشرح
  `من ← إلى`، ووسم «تم التبديل» فقط عند انتقال حقيقي بين المفاتيح داخل نفس الرد.
- قسم «المزوّدات المضافة» في الإعدادات: سطر لكل مزود بشعاره ومسارّه وعدد مفاتيحه،
  زر حذف المزود، وشرائح نماذج قابلة للحذف مع حقل إضافة نموذج.
- شاشة تحميل وشاشة ترحيب لأول تشغيل (الاسم الأول + اختيار من ثلاث صور أفاتار)،
  والاسم والصورة قابلان للتعديل من الإعدادات.

### التشغيل والاختبار
- `requirements.txt` للتشغيل و`requirements-dev.txt` للاختبارات.
- Docker: بناء واجهة + بوابة، منفذ محلي فقط، healthcheck، وعدم نسخ ملفات الأسرار.
- رقم إصدار للبوابة يُرجَع من `/health` و`/status`، وتنبيه في الواجهة إذا كانت النسخة
  المشغّلة قديمة.
- `restart.bat` / `restart.ps1`: يوقفان عملية `gateway.py` المستمعة على 8790 فقط،
  ثم يشغّلان النسخة الجديدة وينتظران ظهور إصدارها. أُصلح `stop.bat`/`stop.ps1` ليعملا
  بالمنفذ لا بعنوان النافذة.
- ترقية السجلات القديمة: خطأ 402 محفوظ من نسخة سابقة يُحوَّل تلقائياً إلى حالة
  `billing` مع إبقاء المفتاح موقوفاً حتى يضغط المستخدم «إلغاء الإيقاف».
- 60 اختباراً للمحرّك و21 اختبار واجهة (Playwright) — 81 اختباراً ناجحاً، منها اختبارات الرمز والصلاحيات وحدود مساحة العمل.
- `.github/workflows/ci.yml`: فحص الكود وبناء الواجهة وتشغيل اختبارات المحرّك عند كل
  push وpull request (اختبارات الواجهة تبقى محلية لأنها تحتاج متصفحاً وخوادم تشغيل).
- كتالوج مزودات (14 مزوداً بشعارات) مع «عرض كل المزودات»، رفيق متحرك بست تعبيرات
  مزاجية، مؤثرات صوتية قصيرة عبر Web Audio، إعدادات مضغوطة، وقسم سياق المجلد
  قابل للطي مع رسائل خطأ عربية/إنجليزية/فرنسية.

## خطوات تالية مقترحة

1. **حفظ المحادثات في قاعدة البيانات**: لتفادي حد `localStorage` (نحو 5MB) ومزامنتها.
2. **جدولة تحديث النماذج** تلقائياً في الخلفية بدل الضغط اليدوي، مع مراعاة حدود المزود.
3. **إحصاءات استخدام** يومية/أسبوعية لكل مفتاح ومزود.
4. **مجلدات المحادثات** وبحث شامل داخل كل المحادثات.
5. **تشغيل كخدمة**: خدمة Windows أو حاوية تعمل عند الإقلاع.
6. **مصادقة متعددة المستخدمين** إن أردت نشر التطبيق خارج الجهاز — التصميم الحالي محلي.

## قيود معروفة

- الحدود المعروضة محلية وليست رصيد المزود الحقيقي.
- لا تُعرض مفاتيح API كاملة بعد حفظها؛ يمكن استبدالها لا استرجاعها.
- يلزم إعادة تشغيل البوابة بعد تعديل ملفات Python؛ استخدم `restart.bat`. تظهر
  الواجهة تنبيهاً عندما تكون البوابة المشغّلة بنسخة أقدم من الواجهة.
- حاوية Docker تُبنى وتعمل محلياً على `127.0.0.1:8790`؛ مسار سياق المجلد داخل الحاوية
  هو `/workspace` المرتبط بمجلد `workspace/` في المشروع، فلا تعمل مسارات Windows
  الكاملة داخلها.
